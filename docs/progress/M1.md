# M1: trustworthy core and reference gate

**Status: complete. Acceptance criteria met.**

## What was built

| Package | What it does |
|---|---|
| `internal/wire` | The LL1 line format, a minimal ULID, HMAC signing, and a forward-compatible parser that finds a token inside arbitrary wrapping |
| `internal/emit` | Shape profiles, a self-rotating file writer, a stdout writer, the safety rails, and the emitter itself |
| `internal/adapter` | The `Sink` interface, the optional `PartialReporter` capability, and the `filesink` reference adapter |
| `internal/verify` | Roaring-bitmap ledgers, the adaptive settle window and judgement state machine, the anomaly classifier, and the bisecting verifier |
| `internal/report` | The normative Prometheus metric set and text or JSON gap reports |
| `internal/refpipe` | refgood, refbad, and the self-validation gate |
| `cmd/lossledger` | `doctor`, `emit`, `verify`, `run`, `selfcheck` |

## Acceptance criteria

- **refbad caught with exactly the injected ranges.** The gate asserts
  range-for-range equality on MISSING and DUP_BUG, and coverage on ORDER.
  14 of 14 checks pass at seeds 1, 2, 3, 7, 11 and 101.
- **refgood clean, including a crashed emitter.** A truncated epoch produces
  zero phantom missing sequences.
- **`false_missing_total` is zero throughout.** Checked explicitly in the gate
  for both reference pipelines.
- **Same seed produces identical emitter output.** Asserted byte for byte in
  `TestEmitterDeterminism`.
- **Safety rails are in place before any fault injection exists**, as the PRD
  requires. The emitter resolves its root through symlinks once and refuses
  every path that escapes it, and the rate cap needs an explicit override.

## Two design problems the gate found

Both were found by the gate failing, which is the gate doing its job.

**1. Partial multi-line delivery was invisible.** When a stack trace loses its
continuation lines, the parent sequence still arrived exactly once, so
`CountRange` saw a clean range, never bisected, and never looked closer. In
production this would have meant partial delivery was never detected at all.

Fixed by adding `PartialReporter`, an optional adapter capability. A sink that
can answer "which sequences in this range arrived incompletely" gets partial
detection. One that cannot simply does not implement it, and its reports say so
rather than quietly reporting no partials.

**2. A sink could not tell a truncated event from a whole one.** The
continuation marker carried only its own index, so the highest index that
arrived looked like the total. The withheld lines were exactly the ones we
could not see.

Fixed by adding an `of=` field to the LLC marker declaring the expected total.
It is omitted when zero, so older lines still parse.

## Deviations from the PRD

- **Commit message format.** The PRD asks for conventional commits. The owner
  chose the drip skill's convention instead: three to five lowercase words with
  no prefix.
- **ULID implemented rather than imported.** About 90 lines, against the PRD's
  preference for the standard library. Recorded in `docs/decisions/`.
- **The LLC marker is keyed, not positional.** PRD section 7.1 writes it as
  `LLC|src|ep|seq|n=<k>`, which mixes positional and keyed fields. It is keyed
  throughout here so one parser handles all three line kinds.

## What is not done

M2 through M5. No real store adapter exists, so nothing here has been run
against Elasticsearch, ClickHouse or Loki. The `filesink` adapter is a
reference, not a product.
